# 초기 밈코인 초단기 트레이딩 자동화 시스템 — 설계 제안서

> 상태: **설계 검토 단계 (코드 없음)**
> 대상 체인: Solana
> 작성일: 2026-08-22

---

## 0. 결론 요약 (먼저 읽을 것)

리서치 결과 세 가지가 명확합니다.

1. **"극초기 진입 속도" 경쟁은 이미 끝난 게임입니다.**
   2026년 스나이퍼 시장은 전략 레이어가 수렴했고, 승부는 인프라(베어메탈 코로케이션 +
   Yellowstone gRPC + Jito BAM 멀티릴레이 + 사전 서명 트랜잭션, 총 ~50ms)에서 갈립니다.
   개인이 노트북 + 퍼블릭 RPC로 slot 0~1에 들어가는 건 불가능합니다.

2. **베이스레이트가 잔인합니다.**
   - pump.fun 졸업률: 2026년 5~6월 83만 건 표본 기준 **0.198%** (2025년 0.63% 대비 3.18배 하락)
   - Solana 밈코인 트레이더 90일 기준 **94%가 손실**, 순손실 기준으로는 99% 이상
   - 반면 스나이퍼 지갑들은 87% 승률 — 즉 **당신이 이기려면 그 94%가 아니라 그 87% 쪽에 서야 함**

3. **그래서 만들 가치가 있는 시스템은 "가장 빨리 사는 봇"이 아니라 "가장 잘 거르고 가장 잘 파는 봇"입니다.**
   개인 개발자가 확보 가능한 엣지는 진입 속도가 아니라
   **(a) 러그 필터링, (b) 청산 규율, (c) 모든 의사결정의 기록/복기 루프** 세 가지입니다.
   이 세 가지는 지연시간 예산이 1~3초여도 성립합니다.

## 1. 전제 수정: "팬텀지갑을 연결한다"는 구조적으로 불가능합니다

팬텀은 **사람이 매 트랜잭션을 승인하도록 설계된 브라우저 확장/모바일 앱**입니다.
헤드리스 서명 API가 없습니다. 선택지는 셋뿐입니다.

| 방식 | 실현성 | 평가 |
|---|---|---|
| A. Playwright로 팬텀 UI 자동 클릭 | 동작은 함 | 승인 왕복 수백 ms~수 초, 확장 업데이트마다 파손. **초단기 트레이딩에 사용 불가** |
| B. 팬텀에서 프라이빗 키 export → 봇에 주입 | 동작함 (트로이/불엑스 등이 쓰는 방식) | **메인 지갑 키를 서버에 올리는 것 = 최악**. 절대 금지 |
| C. **봇 전용 키페어를 새로 생성**하고 팬텀에서 자금만 이체 | 권장 | 팬텀은 "금고", 봇 지갑은 "거래 데스크" |

### 권장 지갑 구조 (3계층)

```
[Ledger / 콜드]  장기 보유 · 절대 온라인 노출 없음
       │ 수동 이체
[Phantom 핫]     운영 자금 풀(트레저리) · 사람만 서명
       │ 수동 이체 (주 1회, 정해진 금액만)
[봇 버너 키페어 N개]  실제 매매 · 여기 있는 돈만 잃을 수 있음
       │ 자동 스윕 (일정 수익 초과분은 팬텀으로 자동 회수)
```

- 버너를 **여러 개** 쓰는 이유: 단일 지갑은 copy-trade 봇에 추적당해 앞에서 먹히고, 런치패드 측 스나이퍼 필터에 걸립니다.
- 키는 **KMS 또는 파일시스템 암호화 저장 + 환경변수 주입**. 리포지토리에 절대 들어가지 않습니다.
- 버너 잔고 상한을 코드로 강제합니다 (`risk.max_burner_balance_sol`). 초과분은 자동 스윕.

## 2. 2026년 시장 구조 (거래 대상 이해)

### 런치패드
- **pump.fun** — 여전히 볼륨/유저 1위, 최대 애그리게이터 연동. 졸업 시 PumpSwap으로 마이그레이션
- **LetsBonk.fun (Raydium LaunchLab)** — 2025년 한때 점유율 과반, 2026년 1월 일 수수료 $352k 피크
- Bags, Meteora DBC, Believe 등 — 롱테일

→ **설계 원칙: 런치패드를 플러그인화**합니다. 점유율이 반년 단위로 뒤집히므로 pump.fun 하드코딩은 부채입니다.

### 토큰 생애주기와 우리가 개입할 지점
```
mint → 본딩커브 구간 → (0.2% 확률) 졸업 → AMM 풀 → 유지 or 소멸
  ↑         ↑                ↑            ↑
  S1        S3               S2           S4/S5
 slot0    시그널진입      마이그레이션    스마트머니추종
 (포기)    (가능)         스나이프(어려움)   (권장)
```

### 반대편에 누가 있는가
번들러(발행과 동시에 다지갑 매집), 인사이더, 개발자 물량, 그리고 프로 스나이퍼.
**필터가 못 걸러내면 이들의 exit liquidity가 됩니다.**

### 수수료 구조 (2026)
- Jito 팁은 우선순위 수수료와 별개 — 8개 팁 계정으로 가고 번들 경매의 주 신호
- 2026 중반 기준 활성 스테이크 95%+ 가 Jito-Solana 클라이언트, 팁이 전체 우선순위 수수료 볼륨의 60%+
- 경쟁 번들의 팁 상한선은 **기대 수익의 50~70%** — 즉 slot-0 경쟁은 수익 대부분을 팁으로 반납하는 구조

## 3. 전략 선택: 어디서 싸울 것인가

| ID | 전략 | 지연 예산 | 경쟁 강도 | 개인 실현성 | 권장 |
|---|---|---|---|---|---|
| S1 | 발행 즉시 스나이프 (slot 0~1) | <50ms | 극한 | ✗ | 하지 말 것 |
| S2 | 졸업/마이그레이션 스나이프 | <200ms | 매우 높음 | △ | 후순위 |
| S3 | **시그널 기반 조기 진입** (발행 후 30초~30분) | 1~3s | 중 | ○ | **채택** |
| S4 | **스마트머니 카피트레이딩** (수익 지갑 추종) | 0.5~2s | 중 | ◎ | **1순위 채택** |
| S5 | 보유 포지션 청산 최적화 (사다리 익절/트레일링) | 초 단위 | 낮음 | ◎ | **필수 (S3/S4에 내장)** |

### 왜 S4 → S3 순서인가
- S4는 **검증 가능한 엣지**가 존재합니다. "지난 30일 실현손익 상위 지갑"은 온체인에서 계산 가능하고,
  그 지갑이 사면 따라 사는 전략은 백테스트가 명확합니다. 시작점으로 측정 가능성이 가장 높습니다.
- S3의 핵심 피처는 리서치에서 정량적으로 확인됩니다:
  **텔레그램 채널을 붙인 런치의 졸업률 1.485% vs 없는 경우 0.166% (8.94배)**,
  **3개 소셜 전부 있으면 1.919% vs 0.110% (17.4배)**.
  즉 소셜 존재 여부는 노이즈가 아니라 실제 예측력이 있는 피처입니다.
- S5는 전략이 아니라 **모든 전략의 수익을 결정하는 부분**입니다. 아래 EV 계산 참조.

### 기대값(EV) 계산 — 왜 필터와 청산이 전부인가

라운드트립 마찰비용:
- 런치패드 거래 수수료 ~1% × 2 = 2%
- 우선순위 수수료 + Jito 팁: 0.0001~0.005 SOL/tx
- 얇은 커브에서의 슬리피지: 1~10%
→ **현실적 왕복 비용 3~8%. 보수적으로 c = 5%로 잡습니다.**

```
필터 없음:  승률 20%, 평균 승 +150%, 평균 패 -100%(러그로 전액 손실)
  EV = 0.20×1.50 - 0.80×1.00 - 0.05 = -0.55  →  거래할수록 파산

필터 있음:  승률 25%, 평균 승 +150%, 평균 패 -40%(손절이 작동)
  EV = 0.25×1.50 - 0.75×0.40 - 0.05 = +0.025  →  거래당 +2.5%
```

**핵심: 필터의 일은 "이기는 거래를 찾는 것"이 아니라 "-100% 사건을 -40% 사건으로 바꾸는 것"입니다.**
그리고 -40%로 묶어두는 건 손절이 아니라 **유동성이 남아있을 때 나가는 규율**이 합니다.
이 두 개만 되면 평범한 진입으로도 EV가 양수로 넘어갑니다. 반대로 이게 안 되면
아무리 빨리 사도 EV는 음수입니다.

## 5. 기술 스택

| 레이어 | 선택 | 근거 |
|---|---|---|
| 전략/오케스트레이션 | **Python 3.11 + asyncio** | 기존 MAIS 컨벤션과 동일. 1~3s 예산 전략에는 충분 |
| 체인 I/O | `grpcio`(Yellowstone) + `solders` / `solana-py` | |
| 실행 | Jupiter Swap V2 API → 이후 프로그램 직접 CPI | Ultra는 유지보수 중단, Swap V2가 후속 |
| 저장 | SQLite → Postgres/Timescale, Redis(핫 상태), Parquet(이벤트 아카이브) | |
| 대시보드 | Streamlit (MAIS와 동일) | |
| (선택) 핫패스 | Rust `solana-sdk` + `jito-searcher-client` | S1/S2로 갈 때만. V8/GC 지연은 튜닝으로 못 없앰 |

- TypeScript를 쓴다면 `@solana/kit` (구 web3.js v2). 구 web3.js 대비 확인 지연 ~200ms 개선 보고.
- **처음부터 Rust로 시작하지 마세요.** S3/S4 전략에서 Rust의 이점은 0이고, 반복 속도만 잃습니다.

## 6. 단계별 로드맵 (게이트 조건 포함)

| Phase | 기간 | 내용 | **다음 단계 진입 조건** |
|---|---|---|---|
| **0. 관측** | 2주 | 거래 0건. gRPC 스트림 녹화 + 스키마 확정 + 러그/생존 라벨링 | 라벨링된 이벤트 데이터셋 확보 |
| **1. 리플레이** | 2주 | 녹화 데이터 기반 백테스트 엔진, Safety Gate 필터 튜닝 | 필터 적용 시 전액손실 이벤트 70%+ 제거 |
| **2. 페이퍼** | 3~4주 | 실시간 페이퍼 트레이딩 (슬리피지/체결 시뮬 포함) | **비용 반영 후 EV > 0**, MDD < 30% |
| **3. 초소액** | 4주 | 실거래 0.05 SOL/건 고정 | 실측 슬리피지 vs 시뮬 갭 < 2%p |
| **4. 사이징** | 4주 | 사이징 확대 + 청산 로직 최적화 | 4주 실현 수익 > 인프라 비용 |
| **5. 복기 루프** | 상시 | Reflection + RAG (MAIS 재사용) | — |
| **6. 대시보드** | 상시 | Streamlit + 텔레그램 알림 | — |

**Phase 0을 건너뛰고 싶은 유혹이 가장 큰데, 여기가 전체 프로젝트의 성패입니다.**
녹화 데이터 없이 만든 필터는 검증할 방법이 없습니다.

## 7. 안전 규칙 (타협 불가)

1. 기본값은 항상 `dry_run=True`. 실거래는 `--live` 명시적 플래그로만.
2. 팬텀/원장 지갑의 프라이빗 키는 **어떤 경우에도 봇 프로세스에 존재하지 않습니다.**
3. 버너 지갑 잔고 상한을 코드로 강제하고, 초과분은 자동 스윕합니다.
4. 일일 손실 한도 도달 시 **자동 정지**하고 사람이 해제하기 전까지 재개하지 않습니다.
5. Safety Gate는 전략 코드에서 우회 불가. 우회 시도는 테스트로 차단합니다.
6. 킬스위치(`scripts/kill_switch.py` 패턴)만이 전량 청산 경로이며 명시적 확인 인자를 요구합니다.
7. `.env`, 키파일, `data_store/`는 커밋 금지.
8. 숫자 하드코딩 금지 — `get_setting("memecoin.risk.max_position_sol")` 형태로만 조회.
